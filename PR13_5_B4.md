# PR13.5 · B4 — SINTONIA DINÂMICA DOS MÓDULOS PASSIVOS

Branch `arena/01a06ff3-echojogo` · base `f5408ee` (B3-FIX) · `SM_VERSION=3` (sem bump) · `FRACTURE_STATE_VERSION=1` · `package.json 0.7.0-alpha`.

## 1. Sistema anterior (PR 9) e o problema

O PR 9 já tinha Sintonia com efeito mecânico real: `MORAL_AFFINITY` (vetor C/G/V por módulo), `calcMoralAffinityMatch` (produto escalar com o perfil moral normalizado, 0..1), `moralTuneFactor` (0 na linha de base 1/3, 1 no alinhamento perfeito) e um **bônus temático por eixo** no Stat Pipeline (`moral:item:<id>:<stat>`): Compaixão → −dano recebido (máx. 5 %), Ganância → +créditos (máx. 8 %), Violência → +dano (máx. 5 %), com orçamento global por eixo (10/14/10 %).

Auditoria "antes" (`audit_pr135/attunement_audit.js`, matriz de 8 perfis × 57 módulos):

| Métrica | PR 9 |
|---|---|
| Efeito máximo de um módulo isolado | ×1,08 (`iman`, créditos) — a maioria ×1,05 |
| Efeito mínimo (divergente) | **×1,00 em todos** — divergência não existia mecanicamente |
| Híbridos C/V (14 módulos) | ×1,006–×1,019: praticamente nulo |
| Estado "DIVERGENTE" | rótulo apenas; nenhum efeito |
| Leitura na loja | "SINTONIA: VIOLÊNCIA · ATUAL: AFIM" — sem motivo, sem número |
| Leitura no TAB | só o contador "MÓDULOS AFINS n/m" |

Conclusão da auditoria B1 confirmada: o sistema existia e conversava com o pipeline, mas o impacto era pequeno demais para ser sentido e a divergência era invisível.

## 2. Filosofia e regra central

"Quanto este módulo combina com a forma como esta run está sendo conduzida." O módulo **lê** `moral` {comp, greed, viol} e reage; **nunca escreve**. Equipar um módulo não gera moralidade (teste B4-18). Toda alteração moral continua vindo de `moralGain` (escolhas, eventos, ações). Não depende de Fracture Theme.

## 3. Arquitetura

### 3.1 Score (determinístico, sem `Math.random`)
```
attunementScore(itemId, prof) = calcMoralAffinityMatch(MORAL_AFFINITY[itemId], prof)   // PR 9, 0..1
```
`null` para módulo sem afinidade (neutro).

### 3.2 Estados (5, finitos) — `ATTUNE_STATES`
| Estado | faixa do score | `mul` (padrão) | `eco` (econômicos) | cor |
|---|---|---|---|---|
| DIVERGENTE | [0, 0,14) | ×0,90 | ×0,95 | `#ff8095` |
| INSTÁVEL | [0,14, 0,26) | ×0,95 | ×0,97 | `#c9a9ff` |
| NEUTRA | [0,26, 0,50) — inclui perfil equilibrado (1/3) | ×1,00 | ×1,00 | `#9db8c8` |
| SINTONIZADA | [0,50, 0,78) | ×1,06 | ×1,03 | `#8ff6ff` |
| RESSONANTE | [0,78, 1] | ×1,12 | ×1,06 | `#ffd166` |

Tuning conservador dentro da orientação (85–92 / 95 / 100 / 105–112 / 112–120). Perfis NEUTRO e EXTREMO (10/10/10) deixam **todos** os módulos em NEUTRA (teste B4-3).

### 3.3 Efeito — três vias, todas derivadas
1. **Pipeline (9 módulos com mod permanente benéfico)** — `calcAttunementPlan` gera um mod `attune:<id>:<stat>` (stacks `replace`) por stat benéfico que leva o bônus do módulo de `(1+b)` para `(1+b·k)`: núcleo +30 % → +33,6 % RESSONANTE / +27 % DIVERGENTE. **Trade-offs nunca são escalados** (mult<1, add<0, flat<0, e `dmgTaken`/`shieldDelay` invertidos): o −10 % de regen da Placa, o +15 % de dano recebido do Coração e o ×0,60 de alcance longínquo do Estilhaço ficam intactos (B4-8/B4-9). Shield passa por `shieldMax/shieldRegen/shieldDelay` do pipeline (clamp 500, nunca enche o escudo). Range usa `meleeRange`/`rangedRange` (B2), nunca o `range` legado.
2. **Campo direto (10 módulos: espinho, su_regen, su_sorte, su_critcura, su_exec, vinganca, condutor, ampulheta, paradoxo, su_vampiro, su_dotcrit)** — não têm mod para escalar. `applyMoralTuning` grava o cache derivado `p.attuneMul[id]` (só quando ≠ 1) e o ponto de consumo lê `attuneFieldMul(p,id)`: dano dos espinhos, regen **do módulo** (não o `mEff.regen`), cura ao abater, cura por crítico, limiar de execução, bônus de vida baixa, saltos de corrente, recarga de dash por abate, `echoBoost`, bônus dos kits, chance de crítico de status. Nunca por frame; nunca salvo.
3. **Bônus temático do PR 9** — mantido como está (aditivo, com orçamento). Para os 33 módulos cujo efeito é hook/proc sem mod permanente benéfico (sb_*, fs_*, crit_*, st_*, dash_*, trans_*, etc.), é o que continua valendo: alinhado ganha até +5/8 %, divergente fica em 0 (perda de sinergia, não malus).

Módulos econômicos (`iman`, `usura`, `eco_risco`, `eco_divida`, `trans_temporal`) usam a banda `eco` (máx. +6 %, mín. −5 %).

### 3.4 Refresh
`applyMoralTuning(p)` (já chamado em `moralGain`, `giveItem`, `removeItemById`, `grantItemInternal`, presets, `resumeRun`, DEV) agora: remove `moral:item:*` **e** `attune:*` → recalcula plano PR 9 → recalcula plano B4 (vê só os mods reais do módulo) → recalcula `p.attuneMul` → `smRefresh`. Sem duplicatas por construção (B4-13/14/15). `_modBelongsToItem` reconhece `attune:<id>:` — remover o módulo leva os seus attune junto (B4-16).

## 13. Limitações / dívida
- 33 módulos de hook/proc só têm o bônus temático do PR 9 (alinhado +5/8 %, divergente 0): a divergência não é *sentida* neles. Escalar procs (duração de janela, stacks, chance de proc) exige tocar cada hook — fora do "mínimo" deste bloco.
- `MORAL_AFFINITY` não foi rebalanceada (Violência 42 %). Reclassificar exige decisão de design por módulo.
- `p.attuneMul` é cache derivado no player (não SM); coberto pelos mesmos pontos de refresh e excluído do save, mas é um segundo caminho além do pipeline.
- Perfil B (Greed moderado) continua em ~90 % CAN_ALL — herdado do B3, não alterado aqui.
